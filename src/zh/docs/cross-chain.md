## 问题：一个地址，多条链

一个 `0x…` 地址，在以太坊、BSC、Arbitrum、Base、Polygon 等所有 EVM 链上都是同一个钱包，同一把私钥控制。但：

- **资金是分链的**：它在以太坊上收过黑客资金，不代表它在 BSC 上也收过。
- **标签也是按链存放的**：一个在以太坊上被制裁的地址，在 BSC 上可能没有任何标签。

所以，只在一条链上筛查，结果干净，并不能说明这个地址在其他链上也干净。一个真实案例（已匿名）：同一个被制裁的黑客地址，在以太坊上筛是拦截、100 分，在 BSC 上筛是通过、0 分，原因就是标签只记在以太坊上。

DART 提供两个工具解决这个问题。

## 工具一：全链 KYA（看所有链上的资金）

接口 `POST /api/v3/screen/kya/multi`，控制台选「全部链（自动识别）」：

- 自动探测这个地址在哪些链、哪些币种上有稳定币流水或标签；
- 每个有内容的通道（链 + 币种）单独筛查、单独存快照；
- 结果里最差的那个通道排在最前（`data.worstLane`），总体分数和风险取最差的通道；
- **只对有流水或标签的通道计费**，空通道不收费。

也可以只筛一条链上的两个币种：`{"address":"0x…","chains":["Ethereum"],"tokens":["usdt","usdc"]}`。

适合：用户提交一个 EVM 地址，你不确定钱会从哪条链来；或者你想一次看清这个地址的全貌。

## 工具二：all_chain_labels（让别的链上的标签也算数）

在 KYA、KYT、全链 KYA 和 MCP 的请求里加 `"all_chain_labels": true`：

- 一次读出这个地址在**所有链上**的标签，当作它自己的标签参与「自身命中」规则判定；
- 从其他链带来的标签单独列在 `otherChainTags` 里，并标明来自哪条链；
- 在交易所豁免下，其他链上的标签可以**取消**豁免，但不能**授予**豁免；
- 合约类标签不跨链（合约在不同链上不是同一个东西）；
- 对 Tron 地址无效（Tron 不是 EVM）；
- 如果跨链标签查询失败，这次筛查会失败，而不是当成「没有标签」放过。

默认关闭；关闭时结果和以前完全一样。

| 你想回答的问题 | 用什么 |
|---|---|
| 这个地址在 BSC 上的资金干不干净 | 普通 KYA，`chain_name: BSC` |
| 这个地址**本身**在任何链上有没有被标为高风险 | KYA + `all_chain_labels: true` |
| 这个地址在所有链上的资金和标签 | 全链 KYA，必要时加 `all_chain_labels: true` |

<div class="callout tip"><b class="t">推荐</b>EVM 地址的充值、提现筛查，建议打开 <code>all_chain_labels</code>。它的开销很小，却能堵住「换条链就查不到」的口子。持续监控也可以带上这个参数。</div>

## 跨链转账（USDC CCTP）

钱还可能通过跨链桥从一条链转到另一条链。目前：

- **USDC 的 CCTP 跨链**（Circle 官方跨链协议）：资金追踪支持按 Circle 官方编号配对，跨链后在目标链上继续追。
- **筛查结果旁的跨链卡片**：显示这个地址或交易的跨链记录、对侧的标签，以及同一私钥在其他链上的地址。只展示，不计分。
- **跨链桥和借贷、收益协议**：作为公共资金池，不往里穿透追（池子里是别人的钱）。

详见 [资金追踪与调查](/zh/docs/tracing/)。

## 支持哪些链

支持的链和币种以接口 `GET /api/v3/chains` 实时返回的为准，控制台的链选择器也读这个列表。返回里的 `address_family` 说明这条链用哪种地址（`evm` 或 `tron`），`default_token` 是不传币种时的默认值。

<div class="callout warn"><b class="t">链名写法</b>请求里的 <code>chain_name</code>、<code>token</code> 不区分大小写（Tron、tron、TRON 都可以）。但<b>规则条件</b>里的 <code>chain_name</code> 必须写小写，例如 <code>tron</code>、<code>ethereum</code>、<code>bsc</code>，写成 Tron 永远不会匹配。</div>
