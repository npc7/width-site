## 筛查和追踪有什么不同

| | 筛查（KYA / KYT） | 交易追踪 |
|---|---|---|
| 回答 | 这个地址、这笔交易有没有风险，该怎么处置 | 这笔钱一跳一跳去了哪里 |
| 输出 | 分数、处置、命中路径、快照 | 一张跟着资金走的图，每个节点带标签 |
| 谁用 | 充提、开户流程，合规复核 | 合规调查员、执法机构、安全事件响应 |

筛查结果进了复核或加强尽调队列，或者发生了被盗、诈骗事件，需要弄清楚**这笔钱后来去了哪**，就用交易追踪。

## 追踪怎么走

从一笔交易出发，沿着资金流向逐跳展开。和筛查一样，追踪按时间顺序走：钱只能先到账、后转出。图上每个对手方都带标签，追到交易所等已知实体，你就知道钱停在了哪里。

### DEX 兑换：在同一笔交易里解析

钱经过 DEX 兑换时，追踪只认**同一笔交易里的兑换结果**：换出来的那部分钱流向哪里，就跟到哪里。它不会沿着池子之后的流水继续追，因为池子里流出去的大多是别人兑换的钱。

### 公共资金池：不穿透

借贷协议、收益协议、跨链桥服务、金库这类**公共资金池**，里面是大量用户混在一起的钱。钱进了池子，再从池子里出来的，已经不能说是「同一笔钱」。所以追踪到这类地址就停下，不往里穿透，避免把无关用户牵连进来。

### 跨链：USDC 的 CCTP

USDC 通过 Circle 官方的 CCTP 协议跨链时，追踪会在目标链上接着追。跨链目的地按「协议 + 链 + 地址」区分：同一个 0x 地址在两条链上，会画成两个节点，不会混在一起。支持的链以产品内显示为准。

## 资金去向怎么分摊

一个地址里，被追踪的钱和它自己的其他钱混在一起。它之后转出好几笔，哪一笔里有多少是被追踪的钱？这就是分摊方法要回答的问题。

| 方法 | 怎么算 | 适合 |
|---|---|---|
| **按比例**（默认） | 被追踪的钱按比例混在地址的余额里，每一笔转出都按比例带走一部分 | 日常调查，速度最快 |
| **先进先出（FIFO）** | 按转账账本的顺序，先到的钱先转出 | 需要按时间顺序说明资金去向，例如回应执法或司法问询 |
| **后进先出（LIFO）** | 按转账账本的顺序，后到的钱先转出 | 对照 FIFO 看结论是否稳定 |

FIFO 和 LIFO 需要逐个读取地址的转账账本，按顺序计算被追踪的钱从哪一笔转出去，所以第一次运行比按比例慢；同一批账本读过之后，切换到另一种方法会快很多。

<div class="callout warn"><b class="t">账本读不全的地址会退回按比例</b>如果某个地址的账本读不全，这个地址会退回按比例分摊，并在图上标出来。对外说明结论时，请把这些节点单独注明。</div>

不同方法得出的金额可能不同，这是方法本身的差异，不是数据错误。写调查报告时，写明用的是哪一种方法。

## 筛查结果旁的跨链卡片

KYA、KYT 结果下面有一张**跨链卡片**，显示：

- 这个地址或这笔交易的跨链记录；
- 跨链对侧地址的标签；
- 同一私钥在其他链上的地址，高风险的标红。

跨链卡片**只展示，不计分**，不影响这次筛查的分数和处置。它的作用是提醒你：这个地址在别的链上可能还有故事。需要把其他链的标签纳入判定，用 `all_chain_labels`；需要筛查其他链上的资金，用全链 KYA。见 [EVM 多链与跨链](/zh/docs/cross-chain/)。

## 调查的推荐步骤

1. **从筛查开始**：先跑一次 KYA 或 KYT，看命中路径和跨链卡片，确定要追的那笔交易。
2. **追踪展开**：从这笔交易出发，先用按比例看主干去向。
3. **看停在哪**：资金停在交易所、发行方冻结地址，还是继续分散。停在交易所的，可以作为协查的线索。
4. **需要时换方法**：要按时间顺序说明去向，切换到 FIFO，用 LIFO 对照。
5. **留证**：筛查快照和追踪结果一起存档，报告里写明方法、时间和参数。
