## 怎么用这份清单

把它复制进你的上线工单，逐项打钩。每一项后面附了原因或链接；拿不准的，[联系我们](/zh/contact/)，工程师会在群里帮你过一遍。

## 一、账号与环境

- [ ] 生产和测试各有可用的 API Key，密钥只放在服务端，不写进前端代码或公开仓库。
- [ ] 请求头用 `X-Api-Key`，不把密钥放在查询参数里（容易进日志）。
- [ ] 生产地址 `https://api.width.live`，测试地址 `https://test-api.width.live`，配置里分开写。
- [ ] 备用域名 `https://api.trustin.bond` 只在主域名**连不上**时使用（域名解析不了、连接被拒）。
- [ ] 合规团队有控制台账号，知道在「合规 › 筛查」复核、在「合规 › 快照」调档。

## 二、规则与参数

- [ ] **每个场景的跳数都显式传入**，不依赖默认值。API 不传时两边都是 3 跳；控制台默认流入 3、流出 1。

| 场景 | 流入 | 流出 |
|---|---|---|
| 充值、收款（看来源） | 3 | 0 或 1 |
| 提现、付款前（看去向） | 0 或 1 | 1 |
| 只查标签（制裁、黑名单） | 0 | 0 |

- [ ] 强制时序保持开启（`force_time_sequence: true`，默认）。见 [为什么按时间顺序追资金](/zh/docs/time-order/)。
- [ ] 交易所豁免保持开启（`cex_immune: true`，默认），除非是针对某家交易所的专项调查。见 [交易所豁免](/zh/docs/exchange-exemption/)。
- [ ] EVM 地址打开 `all_chain_labels: true`，让地址在其他链上的标签也参与判定。见 [EVM 多链与跨链](/zh/docs/cross-chain/)。
- [ ] 时间窗口不设，除非确有需要。缩小窗口会更慢、路径更少。
- [ ] **规则集 id 按环境分开配置**：测试和生产是两个数据库，同一套规则集 id 不同。
- [ ] 只传你自己的规则集或内置、平台规则集的 id。传别人账号或不存在的 id 会被拒绝（HTTP 400，不计费）。
- [ ] 自定义规则里的 `chain_name` 条件写**小写**（`tron`、`ethereum`）。请求参数里的链名不区分大小写，只有规则条件必须小写。
- [ ] 内置规则集只读。要改，先复制，再改副本。见 [自定义规则集与重点关注](/zh/docs/custom-rulesets/)。

## 三、评分与档位

- [ ] **0 分落在「通过」档**。如果评分规则集的档位从 0 开始就是复核，完全没有命中的地址也会显示「需复核」。
- [ ] 档位阈值和你的风险偏好一致，调整过的写明原因和生效时间。见 [评分矩阵与四档处置](/zh/docs/scoring/)、[调优](/zh/docs/tuning/)。
- [ ] 定好**重点关注政策**：有 ★ 命中时至少进入复核，或直接加强尽调。
- [ ] 监管、合作银行点名的对象已经建成 ★ 规则，必要时用 `highlight_tags` 限定到具体实体。
- [ ] 处置逻辑读的是 `score.verdict`，不是 `riskScore`。

## 四、集成

- [ ] 深跳数、活跃地址用异步（`mode: async`），轮询间隔不短于 2 秒。见 [同步还是异步](/zh/docs/api-async/)。
- [ ] 收到 HTTP 429 时退避重试，或改用异步。结果轮询不受这个并发限制。
- [ ] 请求**拿到了响应或超时**后，不要换到备用域名重发：它可能已经在跑，重发会让同一次筛查跑两次、计费两次。
- [ ] 同步请求超时（HTTP 500 且 `data` 带 `job_id`）时，轮询这个 `job_id`，不要重新提交。
- [ ] 任务状态 `FAILED` 是终态、不计费：重新提交新任务，不要继续轮询旧任务。
- [ ] 每次筛查的快照编号（同步 `snapshotId`，异步 `snapshot_id`）存进你的订单、用户或工单记录。
- [ ] `dataStatus.complete = false` 且结果是通过时，当作**暂定**：转人工或稍后重新筛查。见 [数据完整性与快照](/zh/docs/data-status/)。
- [ ] `volume: no_activity` 时，先确认链和币种是否选对。
- [ ] 提交前在你这边校验地址格式。Tron 地址请做 Base58 校验和检查，避免把输错的地址当成正常地址去筛查。
- [ ] KYT 筛查多转账的交易时，用 `event_index` 指定要筛的那一笔，并核对响应里的 `transfer`。见 [交易筛查 KYT](/zh/docs/kyt/)。
- [ ] `force_run` 保持默认关闭，只在需要强制重读链上数据时打开（每次都是一次完整调查）。

## 五、处置流程与留档

- [ ] 四档处置各自的动作、负责人和时限写进内部制度。见 [命中之后怎么处理](/zh/docs/dispositions/)。
- [ ] 拦截档有双人复核，制裁命中的冻结和上报流程明确。
- [ ] 复核记录里写明快照编号、主要命中和判断理由。
- [ ] 规则集、档位每次调整都有变更记录：改了什么、为什么、谁批准、何时生效。见 [怎么向监管解释你的规则](/zh/docs/explain-to-regulator/)。
- [ ] 合规团队能说清每条 ★ 规则对应哪项监管或银行要求。见 [各地监管要求对照](/zh/docs/regulatory-map/)。

## 六、监控

- [ ] 定好哪些地址要持续监控：高风险客户、你自己的充值地址、复核后放行的地址等。
- [ ] 需要自动加入监控的筛查，传 `auto_monitor: true`（默认不加）。
- [ ] 监控沿用筛查时的设置，包括跳数、规则集和 `all_chain_labels`；上线前在控制台的监控页面核对一遍。
- [ ] 监控告警有人跟进，处理方式和筛查命中一致。见 [持续监控](/zh/docs/monitoring/)。
