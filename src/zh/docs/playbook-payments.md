## 一句话

**钱进卡组织和银行通道之前，先过一遍。** 一笔问题资金进了法币通道，合作银行和卡组织可能会重新审视你的整个业务。所以筛查要放在钱「变成法币」之前，而不是之后。

## 三个节点，各筛什么

| 节点 | 筛什么 | 接口 | 推荐参数 |
|---|---|---|---|
| 充卡 / 入金 | 用户转进来的钱从哪来 | KYT，`screen_direction: in` | 流入 3 / 流出 0 |
| 法币出金（off-ramp） | 要换成法币的这笔钱从哪来 | KYT `in`；资金早已在你这里时，对用户的来源地址做 KYA | 流入 3 / 流出 0 |
| 商户结算 / 对外付款 | 钱要打给谁 | 对收款地址做 KYA | 流入 0 或 1 / 流出 1 |

```json
POST https://api.width.live/api/v3/screen/kyt
X-Api-Key: YOUR_KEY

{
  "chain_name": "Tron",
  "tx_id": "充卡交易哈希",
  "token": "usdt",
  "screen_direction": "in",
  "inflow_hops": 3,
  "outflow_hops": 0,
  "in_ruleset_id": 1234,
  "mode": "async"
}
```

`in_ruleset_id` 填你为这家合作方配置的规则集（示例里的 1234 只是占位）。EVM 链建议加 `"all_chain_labels": true`。

## 规则集按合作银行分开

不同的合作银行、卡组织，要求往往不一样：有的要求制裁类「零容忍」，有的对博彩、高风险交易所也有明确要求。

做法：

1. 复制内置规则集（`POST /api/v3/rulesets/clone`），每家合作方一份，名字里写清是哪家、哪个版本。
2. 按对方的要求改规则的严重度、建议动作、门槛；对方点名要知道的对象打 ★。
3. 如果对方对档位也有要求，再复制一份评分规则集调整阈值。
4. 筛查时，按这笔钱要走的通道传对应的 `in_ruleset_id`（或 `ruleset_id`）和 `scoring_ruleset_id`。

每次筛查用的是哪套规则集，都记在快照里。合作方问「某天用的是什么规则」，可以直接拿出来。见 [自定义规则集与重点关注](/zh/docs/custom-rulesets/)。

<div class="callout warn"><b class="t">测试和生产的规则集 id 不同</b>测试环境是独立的数据库，同一套规则集在两边的 id 不一样。上线时记得换成生产的 id。</div>

## 四档处置，不要一刀切

只有「通过 / 拒绝」两种结果，拦多了丢客户，放多了担风险。用四档：

| 处置 | 默认分数 | 充卡 / 入金 | 出金 / 结算 |
|---|---|---|---|
| 通过 | 0–19 | 正常充卡 | 正常出金 |
| 复核 | 20–49 | 暂缓，人工看命中路径 | 暂缓，人工确认 |
| 加强尽调 | 50–79 | 请用户补充资金来源说明和凭证 | 请用户或商户说明用途和收款方 |
| 拦截 | 80–100 | 不充卡；退回或冻结，按政策上报 | 拒绝出金，按政策上报 |

加强尽调的意思是「先问清楚」，不是「直接拒绝」。合作银行要求零容忍的类别，可以把那几类规则的建议动作设成拦截，或调低评分阈值。见 [命中之后怎么处理](/zh/docs/dispositions/)。

## 快照：对账和审计

每次筛查都自动存一份不可篡改的快照，记录当时的参数和完整结果。

- **快照编号跟订单走**：把同步结果里的 `snapshotId`（异步结果里是 `snapshot_id`）存进你的充卡订单、出金单或结算单。
- **对账**：按订单查到快照，`GET /api/v3/snapshots/{snapshotId}` 读回当时的参数、规则集和结论。
- **审计**：在控制台「合规 › 快照」按时间段查看，列表里显示命中了哪些规则；也可以通过 API 批量拉取，生成筛查记录和处置统计。

快照不会因为你后来改了或删了规则集而被改写。重新筛查的结果可能因为新转账、新标签而不同，所以对账以快照为准。见 [数据完整性与快照](/zh/docs/data-status/)。

## 一个对比（已匿名）

某支付公司拿同一个地址做对比：另一款工具判「中低风险、需复核」，DART 判 0 分通过。逐笔拆开后发现，那些风险路径上的资金在时间上是倒着流的，不可能来自风险地址。这类结论可以拿给合作银行看，因为每一步都有时间和金额。见 [为什么按时间顺序追资金](/zh/docs/time-order/)。

## 常见问题

<details><summary>只做稳定币，DART 够用吗？</summary>

DART 专做 USDT / USDC。业务以稳定币为主，可以单独使用；还有其他资产时，和现有工具并用，各管各的资产。

</details>

<details><summary>结果说数据不完整，还能充卡吗？</summary>

<code>dataStatus.complete = false</code> 且结果是通过时，不要直接放行，稍后重新筛查或转人工。结果是复核或以上时，按结果处置，命中本身是可靠的。

</details>
