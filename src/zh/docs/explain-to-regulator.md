## 监管想看到什么

检查时，监管关心的不是你用了哪家工具，而是：

1. 你的设置是**按自己的风险定的**，有理由；
2. 设置**写成了文件**，谁批准的、什么时候改过、为什么改；
3. 你**了解工具本身**：数据从哪来、覆盖多少、有什么局限；
4. 每一个决定都**能复现**：当时用了什么参数、看到了什么、为什么这样处理。

DART 的设计正是为了让这四点容易做到：规则全部可读，每一分都能拆开，每次筛查都存成不可篡改的快照。

## 规则说明模板

下面是一份可以直接改用的大纲。方括号里换成你的实际情况。

```text
一、适用范围
  使用 DART 对 [USDT / USDC] 的 [充值 / 提现 / 转账前 / 收款后] 进行链上筛查。
  覆盖的链：[以 GET /api/v3/chains 返回为准，列出实际启用的链]。

二、筛查时点
  [充值：入账前筛查来源，筛查完成前资产暂不可用]
  [提现：执行转账前筛查收款地址]
  [持续监控：对 [高风险 / 全部] 客户地址按 [频率] 重新筛查]

三、参数及理由
  流入跳数 [3]、流出跳数 [1]：[理由，例如：资金来源追溯三层可覆盖绝大多数分层洗钱；
    资金去向只关心直接对手方，见 DART 文档「跳数怎么设计」]
  强制时序：开启。理由：排除时间上不可能发生的路径，减少误报。
  交易所豁免：开启，但 [被点名的交易所] 通过重点关注规则单独标记。
  最小金额：[10]，过滤粉尘。

四、规则集
  路径匹配规则集：[内置 AML KYA Default v1.3 / 自定义规则集名称与编号]
  主要修改：[列出相对内置版本的修改及原因]
  重点关注（★）规则：[列出，例如被 FinCEN 9714 命令点名的交易所、本地高发的诈骗团伙]

五、评分与处置
  评分规则集：[编号]，档位：0–[19] 通过、[20]–[49] 复核、[50]–[79] 加强尽调、[80]–100 拦截。
  重点关注命中：至少进入复核。
  数据不完整（dataStatus.complete = false）且结果为通过：转人工复核。

六、命中后的处理
  复核：[谁] 在 [时限] 内查看命中路径并记录判断。
  加强尽调：向客户索取 [资金来源说明 / 交易凭证 / 钱包控制证明]。
  拦截：拒绝 [充值入账 / 提现]，[是否上报]，[是否冻结]。
  [双人复核的要求]

七、记录保存
  每次筛查的快照编号存入 [系统名称]，保存 [5 / 8 / 10] 年。

八、复核与调整
  每 [季度] 复核一次：复核量、复核转可疑交易报告的比例、误报样本。
  修改需经 [职位] 批准，记录修改前后的设置、原因、生效时间。
```

## 工具尽职调查资料

香港 SFC 第 12.7.4 段、HKMA 稳定币发行人指引和迪拜 VARA 都要求你在使用前评估链上分析工具。下面是你需要的信息，以及在本文档中心哪里可以找到：

| 评估项 | 内容 | 出处 |
|---|---|---|
| 追踪方法 | 按时间顺序逐跳追踪；时间倒流的路径排除 | [为什么按时间顺序追资金](/zh/docs/time-order/) |
| 判定方法 | 路径匹配规则集 + 评分规则集；每一分都能拆开 | [两套规则集](/zh/docs/rulesets/)、[评分矩阵](/zh/docs/scoring/) |
| 地址库覆盖 | 2 亿已标注地址，九成以上是交易所；九大风险类别 | [标签体系与来源](/zh/docs/labels/) |
| 数据来源和更新 | 官方名单、链上事实、情报团队采集核实；新官方动作当天跟进 | [标签体系与来源](/zh/docs/labels/) |
| 准确性控制 | 入库三道检查、可撤销、误标可快速更正 | [标签体系与来源](/zh/docs/labels/) |
| 数据完整性 | 每份结果标明数据是否完整 | [数据完整性与快照](/zh/docs/data-status/) |
| 已知局限 | 见下 | 本页 |
| 留档 | 不可篡改的快照 | [数据完整性与快照](/zh/docs/data-status/) |

**已知局限**（建议如实写进你的评估）：

- 覆盖范围：DART 只做稳定币（USDT、USDC），不覆盖原生币和其他代币；支持的链以接口实时返回为准。
- 跨链：USDC 的 CCTP 跨链可以续追；其他跨链桥和公共资金池（DEX、借贷、收益协议）作为终点，不往里穿透。
- 混淆服务：资金经过混币器之后无法继续往上游追，DART 会把混币器本身作为风险来源标出。
- 未标注地址：没有标签的地址不会命中任何规则；新出现的风险地址需要等标签入库。
- 标签按链存放：EVM 地址请开启 `all_chain_labels`，见 [EVM 多链与跨链](/zh/docs/cross-chain/)。

需要正式的尽职调查问卷回复或材料，请[联系我们](/zh/contact/)。

## 检查时最常被问的 12 个问题

<details><summary>1. 为什么设这个阈值？谁批准的？</summary>

说明你的档位阈值（例如 20 / 50 / 80）和主要规则的门槛，引用你的风险评估：客户类型、业务规模、历史命中情况。附上批准记录。DART 的默认值是起点，可以说明你在默认值基础上做了哪些调整、为什么。

</details>

<details><summary>2. 规则最近一次调整是什么时候？依据是什么？</summary>

拿出修改记录：修改前后的设置、原因（例如某类误报过多、某个新官方动作）、生效时间、批准人。DART 的每次筛查都记录了所用规则集，调整前后的效果可以用快照对比。

</details>

<details><summary>3. 你的规则逻辑有没有经过独立验证？</summary>

说明验证方式，例如：用一批已知结论的历史地址（已确认有问题的和确认正常的）跑一遍，对比结果；或请内部审计、外部顾问复核。DART 的规则和评分公式全部公开，验证人可以逐条核对。

</details>

<details><summary>4. 你追多少跳？为什么够？</summary>

说明流入、流出各自的跳数和理由。参考：流入看来源，多追几跳；流出看去向，一般看直接对手方；远距离关联有递增的资金占比门槛，不会因为加深跳数而产生大量弱关联。见 [跳数怎么设计](/zh/docs/hops/)。

</details>

<details><summary>5. 你是在放行或入账之前筛查的吗？拿出时间证据。</summary>

用快照的时间和你业务系统里放行、入账的时间对比。建议把快照编号存进你的订单或工单记录。

</details>

<details><summary>6. 误报怎么处理、怎么衡量？复核转上报的比例是多少？</summary>

说明你的复核流程，以及定期统计的复核量、处置结果、转可疑交易报告的比例。如果误报多，说明你做了哪些调优（见 [调优：降误报、调档位](/zh/docs/tuning/)）。按时间顺序追踪本身就是降低误报的设计。

</details>

<details><summary>7. 你对工具做了什么尽职调查？它的覆盖和盲区是什么？</summary>

用上面的「工具尽职调查资料」和「已知局限」。

</details>

<details><summary>8. 新的制裁地址或点名命令多快进入你的筛查？有没有做回溯？</summary>

DART 在新官方动作发布当天跟进（例如 FinCEN 9714 命令发布当天上线规则集）。说明你收到更新后对存量客户地址做了哪些回溯筛查，例如用持续监控或批量重新筛查，并保留记录。

</details>

<details><summary>9. 能不能把当时的决定原样复现？</summary>

能。按快照编号调出当时的请求参数、规则集、命中路径和结果。快照不可篡改，即使之后规则集被修改或删除。

</details>

<details><summary>10. 自托管钱包怎么处理？</summary>

说明你如何确认客户对地址的控制（例如让客户从该地址转一笔指定金额），以及对自托管钱包的转账使用哪套规则集和阈值。DART 筛查的是地址和资金，钱包控制证明需要在你的业务流程里完成。

</details>

<details><summary>11. 谁可以推翻拦截？推翻有没有第二个人复核？</summary>

说明推翻拦截的权限和双人复核要求，并把复核意见和快照编号一起留档。

</details>

<details><summary>12. 员工会不会看工具的结果？培训记录在哪？</summary>

本文档中心可以作为培训材料，尤其是 [怎么读结果](/zh/docs/reading-results/)、[评分矩阵](/zh/docs/scoring/) 和 [命中之后怎么处理](/zh/docs/dispositions/)。我们也可以为你的合规团队做一次培训，记录可以作为培训证明。

</details>
