## 一句话

**充值筛付款方的资金来源，提现在签名前筛收款地址。** 两个节点问的问题不同，所以方向、跳数和规则集都分开设。

| 节点 | 问的问题 | 用什么 | 方向 |
|---|---|---|---|
| 充值到账 | 这笔钱从哪来 | KYT（`screen_direction: in`），或对付款方地址做 KYA | 流入为主 |
| 提现签名前 | 钱要打给谁，对方是谁 | 对收款地址做 KYA | 流出为主 |

## 充值：先筛再入账

### 推荐参数

| 参数 | 推荐值 | 说明 |
|---|---|---|
| 接口 | `POST /api/v3/screen/kyt` | 传充值交易哈希 `tx_id` |
| `screen_direction` | `in` | 只筛付款方，看资金来源 |
| `inflow_hops` / `outflow_hops` | 3 / 0（或 1） | 钱从哪来值得多追几跳；流出一般不用看 |
| `in_ruleset_id` | 你的 KYT-IN 规则集，或平台规则集 | 0 = 内置 KYT-IN 默认 |
| `cex_immune` | `true`（默认） | 用户从别家交易所提币过来，不会被别家的其他用户牵连 |
| `all_chain_labels` | EVM 链建议 `true` | 付款方在其他 EVM 链上的标签也算数 |
| `mode` | 活跃地址、深跳数用 `async` | 见 [同步还是异步](/zh/docs/api-async/) |

```json
POST https://api.width.live/api/v3/screen/kyt
X-Api-Key: YOUR_KEY

{
  "chain_name": "Tron",
  "tx_id": "充值交易哈希",
  "token": "usdt",
  "screen_direction": "in",
  "inflow_hops": 3,
  "outflow_hops": 0,
  "mode": "async"
}
```

一笔交易里可能有多笔转账（批量打款、DEX 路由）。用 `event_index`，或 `from_address` / `to_address` 指明你要筛的那一笔；不确定时先调 `POST /api/v3/transaction-transfers` 看清单。结果里的 `transfer` 会写明这次筛的是哪一笔。

<div class="callout warn"><b class="t">筛付款方，不要筛你自己的充值地址</b>你的充值地址可能已经被识别为交易所地址。开着交易所豁免去筛它，会直接返回 0 分、通过，什么也看不到。用 KYT 的 <code>in</code> 方向，或对付款方地址做 KYA。</div>

### 先挂起，再入账

建议到账后先挂起，拿到结果再入账。通过就入账；其他档位进人工队列。如果你的业务要求先入账，至少在结果出来之前**不允许提走**这笔钱。

### EVM 充值

同一个 `0x…` 地址在所有 EVM 链上是同一个钱包，但标签按链存放。充值方在以太坊上被标了制裁，在 BSC 上可能没有任何标签。建议 EVM 充值打开 `all_chain_labels`；想一次看清付款方在所有链上的资金，用全链 KYA。见 [EVM 多链与跨链](/zh/docs/cross-chain/)。

## 提现：签名前筛收款地址

提现还没上链，没有交易哈希，所以用 KYA 筛**收款地址**。

| 参数 | 推荐值 | 说明 |
|---|---|---|
| 接口 | `POST /api/v3/screen/kya` | 传收款地址 |
| `inflow_hops` / `outflow_hops` | 0 或 1 / 1 | 只关心对方是谁、钱直接打给谁 |
| 只查标签 | 0 / 0 | 最快，只看地址自己有没有制裁等标签 |
| `cex_immune` | `true` | 用户提到别家交易所的充值地址，正常放行 |
| `all_chain_labels` | EVM 建议 `true` | 堵住「换条链就查不到」 |

命中制裁、恐怖融资等自身命中规则，直接拦截，不进入签名。提现上链后，可以再对这笔交易做一次 KYT（`screen_direction: out`）留档。

## 被点名的交易所

有些监管动作针对的是某一家交易所，例如 FinCEN 依据 9714 条款对某交易所发布的命令。它是**命令，不是制裁**，处置口径要结合你的业务和法律意见来定。

DART 的做法：

- **平台规则集**：命令 11 月 6 日发布，DART 当天上线了对应的平台规则集，控制台和 API 里直接选用。相关地址在默认设置下**不会**被交易所豁免放过，多跳关联也能看到。
- **重点关注（★）**：如果你平时用自己的规则集，可以在副本里加一条针对这家交易所的规则并打 ★，用 `highlight_tags` 限定到这家实体。命中后单独列出，不管分数多少。

见 [新的制裁或点名命令出来了怎么办](/zh/docs/playbook-new-actions/)、[交易所豁免](/zh/docs/exchange-exemption/)。

## 处置对照

| 处置 | 充值 | 提现 |
|---|---|---|
| 通过（0–19） | 入账 | 进入签名 |
| 复核（20–49） | 挂起，人工看命中路径 | 暂缓，人工确认 |
| 加强尽调（50–79） | 挂起，向用户索取资金来源说明 | 暂缓，请用户说明收款方和用途 |
| 拦截（80–100） | 不入账；按政策冻结、上报 | 拒绝；按政策上报 |
| 有 ★ 命中 | 至少进入复核 | 至少进入复核 |
| `dataStatus.complete = false` 且通过 | 转人工或稍后重筛 | 转人工或稍后重筛 |

档位阈值是默认值，可以按你的风险偏好调。见 [命中之后怎么处理](/zh/docs/dispositions/)。

## 持续监控

一次筛查只代表当时的状态。地址之后可能收到新的问题资金，对手方也可能上新的名单。建议对这些地址开启监控：

- 用户的提现地址簿（常用收款地址）；
- 进入过复核、加强尽调的付款方地址；
- 大额用户的入金来源地址。

筛查时加 `"auto_monitor": true`，地址会按这次筛查的参数加入监控；之后可以在监控页修改。见 [持续监控](/zh/docs/monitoring/)。

## 常见问题

<details><summary>用户从另一家交易所提币充值，会不会因为那家交易所的其他用户被判高分？</summary>

不会。交易所豁免默认开启，路径追到普通交易所就停止。被制裁或带其他高风险标签的交易所不豁免。

</details>

<details><summary>充值量很大，同步调用会不会被限流？</summary>

每个接口最多同时处理 300 个请求，超出的会排队，最长等 60 秒，仍没有空位就返回 429。量大时用异步模式，结果轮询不限流。见 [认证、环境与错误](/zh/docs/api-basics/)。

</details>
