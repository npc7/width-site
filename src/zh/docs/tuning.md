## 先定位：问题出在哪一层

一份结果由三层决定，调优也按这三层来：

| 层 | 决定什么 | 典型问题 | 去哪改 |
|---|---|---|---|
| 参数 | 追多远、看什么数据 | 跳数太深、时序被关了、交易所豁免被关了、最小金额太低 | 筛查请求 / 控制台高级选项 |
| 规则（路径匹配规则集） | 什么算命中 | 远处的弱关联命中太多；想对某个实体更敏感 | 复制规则集后改规则 |
| 评分（评分规则集） | 命中有多严重、落在哪一档 | 0 分也是复核；复核量太大；拦截太松 | 复制评分规则集后改矩阵、权重、档位 |

控制台的结果页会按「参数 → 规则 → 评分」三层列出这次用了什么设置、哪些规则命中，便于你判断该改哪一层。

## 最快的验证方法：重新判定，前后对比

在控制台的筛查结果页：

- 只改规则集、评分规则集或交易所豁免时，可以用**原任务重新判定**：不重新追资金，约 1 秒内出结果，**不算一次新的筛查**；
- 前后两次结果并排对比，看分数、处置、命中各变了什么；
- 还可以直接改评分参数试算，满意了再保存到你的评分规则集。

建议的调优流程：

1. 挑 20–50 个有代表性的历史地址：确认有问题的、确认正常的、你觉得被误判的。
2. 逐个看现在的结果，找出误判集中在哪一层。
3. 改一处，重新判定，对比。
4. 满意后，把新规则集或评分规则集用到生产，并**记录修改原因和生效时间**（监管会问，见 [怎么向监管解释你的规则](/zh/docs/explain-to-regulator/)）。

## 常见问题和改法

### 0 分也显示「需复核」

原因几乎都是评分规则集的档位从 0 开始就是「复核」。完全没有命中的地址，分数是 0，也会落进复核档。

改法：复制评分规则集，把档位改成 0 分落在「通过」（例如 0–19 通过）。改之前确认你的业务方（如果下游系统按 verdict 做决策）知道这个变化。

### 复核太多

按顺序检查：

1. **强制时序有没有开**：关掉时序会多出很多时间上不可能发生的路径。日常筛查请开启。
2. **交易所豁免有没有开**：关掉后，交易所其他用户的风险会算到你头上。
3. **跳数是不是太深**：日常充值筛查流入 3 跳通常足够；提现、转账前流出 1 跳。
4. **复核档下限是不是太低**：例如把复核下限从 20 提到 30，减少边缘情况进入人工。
5. **远距离门槛是不是太低**：提高 2–5 跳分层暴露规则的 `risk_rate` 门槛。

### 远处的弱关联老是命中

- 提高对应规则的 `risk_rate` 门槛，或给规则加金额条件（例如 `amount > 1000`）；
- 减少流入跳数；
- 对中低风险类别（例如博彩），只保留 1–2 跳的规则。

### 想对某类风险更严格

- 降低这类规则的门槛，或去掉 `risk_rate` 条件只看金额；
- 把规则的 `risk_level` 调高（影响评分权重）；
- 在评分规则集里调高对应格的基础分；
- 如果是「沾到某个实体就要知道」，用 ★ 重点关注，见 [自定义规则集与重点关注](/zh/docs/custom-rulesets/)。

### 想对某家被点名的机构单独处理

不要为此关掉交易所豁免。用平台规则集（例如 FinCEN 9714 命令发布当天上线的规则集），或自己写一条按实体匹配的规则并打 ★：

```json
{
  "direction": "both",
  "min_hops": 1,
  "max_hops": 3,
  "conditions": [
    { "parameter": "tertiary_category", "operator": "IN", "value": ["<实体名>"] }
  ],
  "is_highlighted": true
}
```

### 结果和另一款工具不一致

先把两边设置对齐再比较：跳数、时序、交易所豁免、最小金额、时间窗口。最常见的差异来源是时序：DART 默认排除时间上不成立的路径。见 [为什么按时间顺序追资金](/zh/docs/time-order/)。

## 改动的影响范围

- 规则集和评分规则集是**你账号自己的**，改动只影响用它的筛查。
- 已经生成的**历史快照不会改变**。
- 如果你的系统按 `score.verdict` 自动放行或拦截，改档位会直接改变线上行为，建议先在测试环境验证（测试环境的规则集 id 和生产不同）。
