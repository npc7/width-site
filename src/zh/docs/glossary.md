## 筛查类型

| 术语 | 解释 |
|---|---|
| **KYA**（Know Your Address） | 地址筛查。输入一个地址，追它的资金来源和去向，按规则集判定。见 [地址筛查](/zh/docs/kya/) |
| **KYT**（Know Your Transaction） | 交易筛查。输入一笔交易，筛付款方（来源，`in`）、收款方（去向，`out`）或两边（`both`）。见 [交易筛查](/zh/docs/kyt/) |
| **只看标签** | 流入、流出跳数都传 0。不追资金，只看地址自己的标签，速度最快。结果里 `dataStatus.paths` 为 `labels_only`。见 [制裁与只看标签](/zh/docs/sanctions/) |
| **全链 KYA** | 一次筛一个地址在所有链、所有币种上的情况（`/api/v3/screen/kya/multi`）。每个有流水或标签的通道单独筛、单独计费，最差的排最前。见 [EVM 多链与跨链](/zh/docs/cross-chain/) |
| **all_chain_labels** | 筛 EVM 地址时，把这个地址在其他链上的标签也当作它自己的标签参与判定。带来的标签列在 `otherChainTags` 里 |

## 资金路径

| 术语 | 解释 |
|---|---|
| **跳数** | 一跳就是一次转账。直接对手方在第 1 跳，再往外一层是第 2 跳。见 [跳数怎么设计](/zh/docs/hops/) |
| **流入 / 流出** | 流入是往上游追，问「钱从哪来」（`inflow_hops`）；流出是往下游追，问「钱去了哪」（`outflow_hops`）。传 0 表示这个方向不追 |
| **强制时序** | 要求路径上每一跳的时间不早于上一跳，资金只能沿时间正向流动。默认开启（`force_time_sequence`）。见 [为什么按时间顺序追资金](/zh/docs/time-order/) |
| **交易所豁免** | 被筛地址是普通交易所地址时直接返回 0 分；路径追到交易所就停止。被制裁或带其他高风险标签的交易所不豁免（`cex_immune`，默认开启）。见 [交易所豁免](/zh/docs/exchange-exemption/) |
| **CCTP** | Circle 官方的 USDC 跨链协议。资金追踪按 Circle 的官方编号配对，跨链后在目标链上继续追 |
| **FIFO / LIFO** | 资金追踪里的两种分摊算法：先进先出、后进先出。另一种是默认的按比例分摊。见 [调查与执法](/zh/docs/playbook-investigations/) |

## 命中形态

| 术语 | 解释 |
|---|---|
| **自身命中** | 被筛地址自己带有风险标签，例如它本身就在制裁名单上。规则的 `max_hops` 为 -1。最强信号，直接按自身命中分计分 |
| **直接暴露** | 第 1 跳的直接对手方带有风险标签，且金额超过门槛 |
| **分层暴露** | 第 2 跳及更远的间接关联。跳得越远，要求的风险资金占比越高 |

## 金额与占比

| 术语 | 解释 |
|---|---|
| **风险资金占比（risk_rate）** | 一条路径上最小的一笔转账 ÷ 这条路径的最后一笔转账。用来判断远距离路径算不算命中。结果里是 `riskRatePct`。见 [资金占比与门槛](/zh/docs/fund-share/) |
| **资金占比** | 去重后的风险金额 ÷ 地址链上总流入（或总流出）。用来算分数，和 risk_rate 不是一回事 |
| **分母** | 算资金占比时用的地址链上总流量，不是路径图里的流量。来源记在 `scoreOverview` 里 |

## 规则集

| 术语 | 解释 |
|---|---|
| **路径匹配规则集** | 决定「什么算违规」。每条规则是一组条件，全部满足才命中。类型有 `kya`、`kyt_in`、`kyt_out`。见 [两套规则集](/zh/docs/rulesets/) |
| **评分规则集** | 决定「有多严重、怎么处置」。把命中折算成 0–100 分并分档。类型是 `scoring`。见 [评分矩阵](/zh/docs/scoring/) |
| **内置规则集** | 对所有人可见、只读的默认规则集，例如 AML KYA Default v1.3。要改，先复制一份 |
| **平台规则集** | DART 针对某个官方动作发布的规则集，例如 FinCEN 9714 命令发布当天上线的规则集，直接选用。见 [新的制裁或点名命令](/zh/docs/playbook-new-actions/) |
| **贡献矩阵** | 评分规则集的核心：按「方向 × 跳数 × 严重度」给出每一格在资金占比 100% 时的满分贡献 |
| **严重度权重** | 严重、高、中、低四档对应的系数，默认 1、0.8、0.6、0.3 |
| **重点关注（★）** | 给规则打的标记。被 ★ 的规则一旦命中，单独列在 `highlightedHits` 里，不管分数多少。只影响展示，不改分数。见 [怎么读结果](/zh/docs/reading-results/) |
| **highlight_tags** | 把 ★ 限定到具体实体：只有对手方标签里含这些名字时，才算重点关注命中 |

## 处置

| 术语 | 解释 |
|---|---|
| **处置档位** | 分数落在哪一档，就给出哪个建议：accept（通过，0–19）、review（复核，20–49）、edd（加强尽调，50–79）、block（拦截，80–100）。阈值可调。见 [命中之后怎么处理](/zh/docs/dispositions/) |
| **EDD**（加强尽调） | Enhanced Due Diligence。暂缓处理，向客户索取资金来源说明和凭证，再决定是否放行 |

## 留档与数据

| 术语 | 解释 |
|---|---|
| **快照** | 每次筛查自动保存的不可篡改记录，包括当时的参数和完整结果。按 `snapshotId` 读回。见 [数据完整性与快照](/zh/docs/data-status/) |
| **dataStatus** | 结果背后的数据是否完整。`complete` 为 false 时，干净的结论只能算暂定 |
| **持续监控** | 把地址加入监控，之后持续按设定的参数重新检查，风险变化时产生提醒。筛查时加 `auto_monitor: true` 即可加入。见 [持续监控](/zh/docs/monitoring/) |

## 接入

| 术语 | 解释 |
|---|---|
| **同步 / 异步** | 同步直接返回结果；异步（`mode: async`）立刻返回 `job_id`，再轮询结果。见 [同步还是异步](/zh/docs/api-async/) |
| **MCP** | Model Context Protocol。DART 把同样的能力做成 MCP 工具，AI 助手可以直接筛查、读结果、管理规则集。见 [AI 助手（MCP）](/zh/docs/mcp/) |
