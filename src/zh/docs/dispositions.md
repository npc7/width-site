## 四档处置，各做什么

| 处置 | 默认分数 | 建议动作 | 谁来做 | 留什么 |
|---|---|---|---|---|
| 通过 | 0–19 | 自动放行 | 系统 | 快照编号 |
| 复核 | 20–49 | 人工看命中路径，决定放行或升级 | 合规专员 | 快照编号 + 复核意见 |
| 加强尽调 | 50–79 | 暂缓，向客户索取资金来源说明和凭证 | 合规专员，必要时主管 | 快照编号 + 客户材料 + 结论 |
| 拦截 | 80–100 | 拒绝；按政策决定是否冻结、上报 | 合规主管，建议双人复核 | 快照编号 + 处置决定 + 上报记录 |

另外两条规则建议写进你的政策：

- **有重点关注（★）命中**：至少进入复核，不管分数多少。
- **数据不完整**（`dataStatus.complete = false`）且结果是通过：转人工，或稍后重新筛查。

## 复核时看什么

打开结果里的命中路径，逐条回答：

1. **对手方是谁**：什么标签？哪一类风险？（大类、实体）
2. **离得多近**：第几跳？直接对手方和三跳之外，含义完全不同。
3. **方向**：钱是流进来（来源有问题）还是流出去（去向有问题）？
4. **多少钱、占多少**：`exposureAmount` 和资金占比。占比越高，越像真的关联。
5. **时间对不对**：风险资金的时间是否早于它流到这个地址的时间？（开启强制时序时，DART 已经替你排除了时间上不成立的路径。）
6. **有没有合理解释**：例如对手方是一个被点名但有大量正常用户的交易所，而这笔资金是用户正常提币。

## 复核决策流程

```text
命中
 ├─ 自身命中（地址自己带制裁 / 恐怖融资 / 执法冻结等严重标签）
 │    → 拦截；制裁类按政策冻结并上报
 ├─ 直接暴露（1 跳）
 │    ├─ 严重类别（制裁、恐怖融资、执法冻结、非法市场）→ 拦截或加强尽调
 │    └─ 其他类别 → 看金额和占比：占比高 → 加强尽调；占比低且有合理解释 → 放行并记录
 └─ 分层暴露（2 跳及以上）
      ├─ 占比高、跳数少、风险类别严重 → 加强尽调
      └─ 占比低、跳数多 → 放行并记录理由（远距离弱关联）
```

这只是起点，请按你的业务和监管要求调整，写进你的规则说明。

## 加强尽调要什么材料

根据风险类型，向客户索取：

- 资金来源说明：这笔钱是从哪里来的、做什么用的；
- 交易凭证：交易所提币记录、OTC 交易合同、收款截图；
- 钱包控制证明：从该地址转一笔指定金额，证明客户控制这个地址；
- 必要时：身份信息更新、业务背景说明。

拿到材料后，结合命中路径判断是否放行，并留档。

## 拒绝、冻结和上报

- **拒绝**：充值不入账（或按你的政策退回），提现不执行。
- **冻结**：制裁命中一般要求立即冻结，且不能预先通知客户（以你所在地法规为准）。
- **上报**：按当地要求提交可疑交易报告（例如香港向联合财富情报组、新加坡向 STRO、美国 SAR）。上报材料里可以引用快照编号、命中路径（对手方、跳数、金额、时间），这些都是可核对的链上事实。

## 复核记录模板

```text

分数 / 处置：         重点关注命中：[有 / 无，规则名]
主要命中：[对手方标签、跳数、方向、金额、占比]
数据完整性：[complete / 不完整原因]
判断：[放行 / 加强尽调 / 拒绝]
理由：
补充材料：[客户提供的说明、凭证]
复核人：              第二复核人（如需）：
日期：
```
