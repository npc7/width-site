## 为什么要看数据完整性

一份「0 分、通过」的结果，可能意味着两件事：

1. 数据完整，确实没发现问题；
2. 部分数据没读到，所以没发现问题。

这两种情况必须区分开。DART 在每份结果里用 `dataStatus` 告诉你是哪一种。

## dataStatus 的字段

| 字段 | 取值 | 含义 |
|---|---|---|
| `complete` | true / false | false 表示有部分数据没读到。此时干净的结论只能算**暂定**，请重新筛查或人工复核 |
| `paths` | `complete` | 调查完成，所有规则都跑过了 |
| | `labels_only` | 你传了两边都是 0 跳，只检查了地址自己的标签（按要求跳过追踪，算完整） |
| | `cex_exempt` | 普通交易所地址，按豁免直接返回（算完整） |
| | `failed` | 仅 KYT 双向筛查时出现：某一侧没读到 |
| `volume` | `ok` | 地址在这个币种上有转账，分母正常 |
| | `no_activity` | 地址在这个币种上没有转账，`scoreOverview` 全为 0 |
| | `unavailable` | 总流量查询失败，分母退回到路径流量，**分数只会偏高**；命中不受影响 |

## 推荐的处理方式

| 情况 | 建议 |
|---|---|
| `complete: true` | 按分数和重点关注正常处置 |
| `complete: false`，结果是通过 | 不要直接放行。稍后重新筛查，或转人工复核 |
| `complete: false`，结果是复核或以上 | 按结果处置；命中本身是可靠的 |
| `volume: no_activity` | 地址在这条链这个币种上没用过。确认链和币种是否选对，EVM 地址可以试试全链 KYA |

## 任务失败（FAILED）

异步筛查的任务状态最终会是 `COMPLETE` 或 `FAILED`：

- `FAILED` 是**终态**，表示上游调查失败，`error` 字段说明原因，**不计费**。
- 收到 `FAILED` 后请**重新提交**一个新任务，不要继续轮询同一个任务，它不会再变。

见 [同步还是异步](/zh/docs/api-async/)。

## 快照：每次筛查都留档

每次筛查都会自动保存一份**快照**，记录：

- 请求参数：链、地址或交易、跳数、规则集和评分规则集、交易所豁免、时序等；
- 当时的完整结果：分数、处置、命中、路径证据、数据完整性。

快照**不可篡改**。即使你之后删除了规则集，历史快照也不会被改写。

| 在哪里 | 怎么找 |
|---|---|
| 控制台 | 「合规 › 快照」，可按账号、时间筛选，列表里显示命中了哪些规则 |
| API 同步筛查 | 响应里的 `data.snapshotId` |
| API 异步筛查 | 结果里的 `data.snapshot_id` |
| 读回快照 | `GET /api/v3/snapshots/{snapshotId}` |

<div class="callout tip"><b class="t">把快照编号存进你自己的系统</b>建议在你的用户、订单或工单记录里保存快照编号。监管检查、用户申诉、内部复核时，按编号调出当时的完整证据，不需要重新筛查（重新筛查的结果可能因为新转账、新标签而不同）。</div>

## 同样的参数，结果为什么会不同

- 地址有了新转账，或对手方有了新标签；
- 默认会复用相同参数的近期调查结果；如果你需要强制重新读取链上数据，加 `force_run: true`（会产生一次完整调查的开销）；
- 你换了规则集或评分规则集。
