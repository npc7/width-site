## 为什么要监控

一次筛查只代表**那一刻**的结论。之后可能发生：

- 地址又收到了新的资金，其中有来自风险对手方的；
- 和它有过往来的地址，后来被列入制裁名单、被发行方冻结，或被标为黑客、诈骗地址；
- 地址本身被打上了新的标签。

这些变化不会自动反映到旧快照里，快照是不可篡改的存档。要在变化发生后知道，就需要持续监控。

## 什么时候用

| 场景 | 为什么 |
|---|---|
| 名单更新后的回看 | 新的制裁或执法动作发布后，已经通过的地址需要重新判断 |
| 高风险客户 | 复核或加强尽调后放行的客户，需要持续关注 |
| 你自己的充值地址 | 充值地址持续收钱，来源随时可能变化 |
| 白名单、长期合作的对手方地址 | 合作期间对方的风险状况可能变化 |

不是所有地址都需要监控。建议从上面几类开始，按你的风险政策决定范围。

## 怎么把地址加入监控

在 KYA 或 KYT 请求里加 `"auto_monitor": true`：

```bash
curl -X POST 'https://api.width.live/api/v3/screen/kya' \
  -H "X-Api-Key: $DART_API_KEY" -H 'Content-Type: application/json' \
  -d '{"chain_name":"Ethereum","address":"0x…","inflow_hops":3,"outflow_hops":1,"all_chain_labels":true,"auto_monitor":true}'
```

- **默认不加入监控**。不传这个参数时，按你在监控设置里的开关处理，这个开关默认也是关闭的。
- **一个地址、一个币种对应一个监控**。之后再用 `auto_monitor` 筛查同一个地址，会续期已有的监控，不会重复创建。
- **KYT 加入的是被筛查的那一端**：`screen_direction: in` 监控付款方，`out` 监控收款方，`both` 两端都监控。

## 监控用什么设置

监控沿用加入它的那次筛查的设置：

| 设置 | 说明 |
|---|---|
| 路径匹配规则集 | 你在筛查里指定的 `ruleset_id`；没指定时用监控的默认规则集 |
| 评分规则集 | 同筛查 |
| 跳数 | 同筛查。某一边传 0，监控里这一边也不追；两边都是 0 的筛查，监控按 3 / 3 跳运行 |
| 最小金额、每跳最大节点数 | 同筛查 |
| 交易所豁免、强制时序 | 同筛查 |
| `all_chain_labels` | 同筛查，监控每次运行都会合并其他链上的标签 |

如果之后用 `all_chain_labels: true` 重新筛查一个已经在监控中的地址，这个地址的自动监控也会打开 `all_chain_labels`。

<div class="callout tip"><b class="t">在监控页面改设置</b>每一项设置都可以在控制台的监控页面修改，包括评分规则集、场景、到期时间和单边 0 跳，不需要重新筛查。上线前建议在监控页面核对一遍，确认和你的风险政策一致。</div>

## 监控告警

监控运行时产生的结果同样存为快照，告警带有快照编号，可以用 `GET /api/v3/snapshots/{snapshotId}` 读回，快照的 `source` 字段为 `monitoring`。处理告警和处理筛查命中的方式一样：看分数和处置，看重点关注，打开命中路径核对证据，再按你的流程复核、加强尽调或拦截。见 [命中之后怎么处理](/zh/docs/dispositions/)。

## 推荐做法

1. **先定范围**：哪些地址进监控，写进你的风险政策。
2. **加入时用对设置**：监控沿用筛查的设置，加入前先确认跳数、规则集和 `all_chain_labels`。EVM 地址建议打开 `all_chain_labels`。
3. **告警有人跟进**：指定负责人和处理时限，处理结果记在复核记录里，附快照编号。
4. **定期回顾**：不再需要的监控，在监控页面调整到期时间。
